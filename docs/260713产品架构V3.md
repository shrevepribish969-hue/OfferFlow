# OfferFlow AI Architecture Design（Version 3.0）

## 1. Architecture Overview

OfferFlow 是一款 AI Native 求职工作台，其核心设计目标并不是构建一个能够回答所有问题的大语言模型聊天机器人，而是构建一个能够长期协助用户完成求职任务的 **AI Workspace**。

传统 AI 产品通常以一次对话（Conversation）作为交互单位，缺乏长期上下文。OfferFlow 将系统设计为 **Job Case Driven**，即以每一次岗位投递作为核心对象。

**UI 范式定调：Workspace 优先，AI 作为 Copilot。**
用户日常管理岗位、简历、任务、日程，全部在结构化的 GUI 工作台内进行。AI 不作为强制的唯一入口，而是在涉及“生成、分析、总结、建议”等重度任务时介入（如点击 `✨ Ask AI`）。这保证了多线程求职时的信息管理效率。

---

## 2. Core Execution Pipeline（核心执行链路）

整个系统采用极度解耦的分层架构设计，实现了“控制流”与“数据流”的彻底分离。所有请求遵循以下链路：

**【控制流：自上而下】**
1. **User** -> 在 Workspace 触发指令（点击按钮或输入自然语言）。
2. **AI Assistant** -> 收集当前上下文（页面状态、选中的 Job Case）发送给后台。
3. **Intent Router** -> 这是整个 AI Runtime 的核心入口。它不处理业务，仅负责将自然语言翻译为结构化意图（提取 Action 及对应的 Job Case ID）。
4. **Workflow Engine** -> 纯程序化组件，根据 Router 识别的 Action 调度固定流程。
5. **Agent** -> 业务能力的组合外壳。
6. **Skill** -> 最小的 AI 能力单元，进行大模型推理。

**【数据流：自下而上】**
7. **Skill (Tool Call)** -> 推理完毕，输出标准化的 Tool Call 请求。
8. **Job Case Controller** -> 整个系统的数据中控，拦截所有写入请求。
9. **Database** -> 最终由 Controller 更新至 Supabase。

---

## 3. Domain Model（核心对象设计）

OfferFlow 的所有数据围绕对象展开，目前 MVP 版本包含以下核心对象：

| Object        | 描述                            | 生命周期    |
| ------------- | ----------------------------- | ------- |
| User Profile  | 全局信息，包含 **Master Resume（母版简历）** | 长期存在    |
| Job Case      | 聚合根。一次岗位投递的完整生命周期             | 创建至归档   |
| Resume        | 从母版 Fork 出来的，当前 Job Case 专属简历 | 分支迭代    |
| Interview     | 某一次具体面试的信息                    | 面试结束后固定 |
| Communication | 与 HR、面试官之间的沟通记录               | 持续更新    |
| Reflection    | 单次面试后的复盘结果                    | 面试结束生成  |
| Task          | 由 Workflow 自动生成的待办事项          | 状态流转    |
| Memory        | AI 长期记忆知识库                    | 按需读写    |

---

## 4. Git-flow for Resume（简历版本管理机制）

系统摒弃“完结后统一回流”的设计，采用类似 Git 的分支与合并管理机制：

* **Master Resume (User Profile)**：永远作为唯一主分支（Main）。
* **Job Case Resume**：每次针对新岗位，从母版 Fork 出的一个独立分支。
* **Resume Merge（简历合并）**：当 AI 在优化 Job Case Resume 时，如果发现某个项目经历或技能描述的修改明显优于母版，AI 会主动触发 `Propose Merge`。系统在前端提示用户：“这段描述优于母版，是否同步？”，用户确认后，该局部数据合入 Master Resume。

---

## 5. System Controller（数据一致性中控）

系统引入 **Job Case Controller** 作为整个数据更新的咽喉。

**谁拥有 Job Case？—— Controller。**
Agent 和 Skill 绝不能直接修改数据库。无论是 Resume 优化、面试状态变更，还是新建 Task，所有修改必须以 Tool Call 形式发送给 Job Case Controller。
这类似于前端的 Redux 或后端的 Domain Service，它负责处理并发冲突、触发状态级联更新（如状态变成 Interview 后自动生成 Task），保证了系统的最终一致性。

---

## 6. Agent Architecture

后台根据 Workflow 自动调用对应 Agent。用户始终只面对 AI Assistant，感知不到 Agent 存在。

| Agent               | 主要职责                       |
| ------------------- | -------------------------- |
| Case Manager        | 管理 Job Case 生命周期及 Task     |
| Opportunity Analyst | 分析岗位需求及岗位匹配度               |
| Resume Strategist   | 优化 Resume 并提出 Merge 建议     |
| Interview Coach     | 面试准备、评价及复盘                 |

---

## 7. Skill Library

Skill 是最小 AI 能力单元。拥有独立 Prompt，被多个 Agent 重复调用。MVP 包含十个核心：

1. Job Case Management
2. Workflow Planning
3. JD Analysis
4. Job Matching
5. Resume Analysis
6. Resume Optimization (含 Propose Merge 逻辑)
7. Content Generation
8. Interview Preparation
9. Interview Evaluation
10. Reflection

---

## 8. Workflow Design

**Workflow 永远由程序控制，而不是由 LLM 自主规划。**

例如，新建 Job Case 后：
`Create Job Case -> Intent Router 分发 -> JD Analysis -> Resume Analysis -> Job Matching -> Resume Optimization -> Generate Resume -> Complete`

Workflow 保证了行为可预测性，LLM 仅在具体节点负责推理。

---

## 9. Prompt Architecture

Prompt 作为独立的 AI Asset 管理，不硬编码在业务中。

包含：System Prompt, Skill Prompt, Output Prompt, Evaluation Prompt。
采用按需注入策略（Context Injection），只给模型提供当前任务必需的对象（如只给 JD 不给完整的对话记录）。

---

## 10. Memory Architecture

Memory 是系统长期知识库。不存全量聊天，只存知识。

* **Memory 保存**：长期有效知识（如能力短板、偏好表达）。
* **Memory 读取（Retrieval）**：按 Skill 推理需要，结构化按需读取。
* **Memory 更新（Update）**：由 Workflow 在特定节点（如 Reflection 结束后）统一控制写入。
* **Memory 存储**：支持结构化与语义检索。底层具体用何种向量库或 JSONB 方案由工程层按需实现。

---

## 11. Design Principles

1. **Workspace 为主，Chat 为辅**：GUI 承载管理，AI 负责重度认知任务。
2. **Intent Router 作为入口**：分离意图解析与业务执行。
3. **Git-flow 管理简历**：Master 为主，Fork 为辅，主动提议 Merge。
4. **统一中控**：Job Case Controller 统管所有写操作，Skill 仅输出 Tool Call。
5. **Skill 复用**：优先复用 Skill 解决新问题，而非新增 Agent。
