一、产品定位（Product Position）
目前市面上的求职产品，大致可以分为两类。第一类是 Job Tracker，例如 Huntr、Teal。这类产品的核心价值是记录和管理投递状态，用户需要自己维护岗位信息、更新流程、设置提醒，AI 只是作为辅助功能存在。第二类是 AI Chat Assistant，例如 ChatGPT、Claude。它们能够完成 JD 分析、简历优化、模拟面试等单点任务，但每一次都是独立对话，无法持续理解用户整个求职过程。
OfferFlow 希望解决的是两者之间的断层。它管理的不只是岗位信息，也不是一次次 AI 对话，而是完整的 Job Case。用户无需反复向 AI 描述背景，AI 会持续理解每一个岗位的发展过程，并围绕当前阶段主动提供帮助，使整个求职过程形成连续、可追踪、可沉淀的智能工作流。

二、核心产品对象——Job Case
整个产品最核心的概念不是 Agent，而是 Job Case。
每一个 Job Case 代表用户针对某一个岗位的完整求职过程。例如：腾讯 AI 产品经理就是一个独立的 Job Case。这个 Case 从用户第一次发现岗位开始，到最终 Offer 或 Rejected 结束。它不是一条数据，而是一个持续成长的工作空间。所有与这个岗位相关的信息，都属于同一个 Case。包括：岗位信息（JD）公司信息针对该岗位准备的简历版本Skill Gap 分析AI 修改建议投递记录Follow-up 邮件面试记录面试问题面试总结Offer 信息用户不需要分别进入"简历模块""面试模块""AI 模块"。而是在进入腾讯 Case 后，就能看到所有内容。AI 的所有能力，也全部围绕这个 Case 展开。

三、Job Case 生命周期（Lifecycle）
每一个 Job Case 都拥有自己的生命周期。
整个生命周期可以划分为七个阶段。
① Discovery（发现机会）用户创建新的 Job Case。只需要粘贴 JD、招聘链接，甚至只输入公司名称即可。AI 自动解析岗位信息，识别岗位类别、技术方向、业务领域，并自动完成 Case 初始化。用户几乎不需要填写任何表单。AI 负责完成冷启动。
② Preparation（准备阶段）进入 Preparation 后，AI 开始帮助用户真正准备这个岗位。例如：分析 JD。提取核心技能要求。计算当前简历与岗位的匹配程度。识别 Skill Gap。根据岗位特点生成专属简历版本。推荐需要补充的项目描述。生成 Cover Letter。分析公司背景。这一阶段 AI 的目标只有一个：帮助用户提升这个岗位的竞争力。
③ Application（投递阶段）用户完成投递。Case 状态进入 Applied。AI 自动记录投递时间。根据招聘节奏自动计算 Follow-up 时间。提醒补充材料。整理招聘流程。记录所有沟通记录。这一阶段 AI 不再负责内容生成，而是帮助用户推进流程。
④ Assessment（测评阶段）如果进入笔试、测评等阶段。AI 自动切换工作模式。根据岗位类型推荐对应练习。生成专项练习。整理相关知识。分析历史高频考点。帮助用户快速准备测评。
⑤ Interview（面试阶段）这是整个产品 AI 能力最集中的阶段。AI 会自动读取：当前 JD。当前简历版本。公司背景。历史沟通记录。历史面试表现。然后完成：模拟面试。高频问题预测。STAR 回答优化。追问训练。回答评分。面试结束后。AI 自动生成本次面试总结。提炼核心问题。形成下一轮准备建议。整个过程都发生在当前 Job Case 内。
⑥ Decision（结果阶段）进入 Offer 或 Rejected。AI 不只是记录结果。而是帮助用户进行决策。例如：Offer 对比。薪资分析。岗位发展分析。风险分析。帮助用户做出最终选择。
⑦ Archive（归档阶段）Job Case 虽然结束。但是经验不会结束。整个 Case 自动进入 Career Memory。成为以后所有岗位的重要参考。这也是整个产品最大的价值之一。

四、AI 在产品中的角色
OfferFlow 最大的变化，不是增加了很多 Agent。而是重新定义了 AI。AI 不再是一个聊天机器人。而是每一个 Job Case 的协作者（Case Collaborator）。用户负责推进流程。AI 负责理解上下文。维护长期信息。主动完成分析。持续提供建议。整个过程中。AI 不需要等待用户每一次提问。它会根据当前 Job Case 所处阶段自动切换自己的职责。例如：Discovery 阶段负责解析。Preparation 阶段负责优化。Interview 阶段负责模拟。Decision 阶段负责决策支持。因此。用户看到的是一个 AI。但实际上。背后可能由多个 Agent 协同完成。这种复杂性完全被隐藏。

五、Memory 体系
OfferFlow 的核心竞争力并不是模型。而是持续上下文（Persistent Context）。Memory 可以划分为三个层级。
第一层是 Profile Memory。
保存用户长期稳定的信息。
例如教育背景、项目经历、技能、作品集、求职方向等。
所有 Job Case 共用。

第二层是 Case Memory。
每一个 Job Case 都拥有自己的长期记忆。
包括：JD。
简历版本。
沟通记录。
面试记录。
Follow-up。
AI 分析结果。
这部分数据不会因为聊天结束而丢失。

第三层是 Career Memory。
它不是聊天摘要。
而是整个秋招过程中沉淀出来的成长轨迹。
例如：哪些技能在多个岗位中频繁出现。
哪些类型的问题容易失分。
哪些项目最容易获得认可。
Career Memory 不评价用户。
只记录客观事实。
为下一次求职提供依据。

六、Agent 架构
Agent 并不是产品中的页面,而是产品背后的能力层。

用户永远不会主动选择 Resume Agent 或 Interview Agent。当用户进入某一个 Job Case 时。系统会根据当前阶段自动调用对应能力。例如：Resume Agent 负责维护用户简历与项目画像。JD Agent 负责解析岗位需求。Match Agent 负责计算匹配度并生成优化建议。Interview Agent 负责模拟面试。Reflection Agent 负责总结面试经验。Career Agent 则负责跨 Job Case 分析用户长期成长情况。多个 Agent 共同协作。用户始终只面对一个统一的 AI。

七、产品的核心闭环（Core Loop）我认为，这也是整个产品最重要的地方。很多产品完成一次任务后，价值就结束了。而 OfferFlow 希望形成持续成长。整个闭环应该是：创建 Job Case → AI 协助准备 → 推进招聘流程 → 面试与复盘 → 经验沉淀 → 反哺下一次 Job Case。每完成一个岗位。用户不仅获得一次结果。更获得了一份新的经验。这些经验会持续进入 Career Memory。帮助下一次 JD 分析更加准确。帮助下一次模拟面试更加有针对性。帮助下一次简历修改更加符合岗位要求。因此。OfferFlow 不只是帮助用户管理一次求职。而是让每一次求职经历，都成为下一次成功的基础。

八、产品未来
第一阶段（P1），产品聚焦于单个 Job Case 的全生命周期管理，这是产品的核心价值，也是 MVP。
第二阶段（P2），在积累足够多的 Job Case 后，系统开始构建 Career Intelligence（职业智能）。AI 不再只分析某一个岗位，而是分析整个求职市场。例如，它可以发现 AI 产品经理岗位中最常出现的能力要求、不同公司的能力差异、用户在多个岗位中的技能短板，以及整个秋招过程中个人竞争力的变化趋势。这一阶段，产品的价值将从帮助拿下一个 Offer，升级为帮助用户持续成长为更优秀的职业人才。
